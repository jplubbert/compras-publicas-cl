# Plan de T-01

## Objetivo
Dejar el repo con un entorno de herramientas fijado y local, y con un esqueleto andante que se verifica sin red, para
que T-02 a T-15 trabajen sobre él (tarea `tooling`, sin REQ; mandan la descripción de la tarea y su `verify`):

- Herramientas solo desde `.tools/` (pedido del usuario del 2026-10-21; R-01): mise de una versión fijada, con su
  sha256 verificado, en `.tools/bin/mise`. Con `MISE_DATA_DIR=.tools/mise` instala terraform, uv, python 3.12 y node 22
  en las versiones exactas de `mise.toml`, con sus checksums en `mise.lock`. Sin sudo y sin nada global.
- DEC-005: `scripts/setup.sh` es el único paso con red. Instala las herramientas (Terraform queda en `.tools/`), corre
  `uv sync` y el `npm ci` de `dataform/`, y precarga en `.tools/providers` los proveedores google, google-beta, archive y
  random. El resto (`lint`, `test`, `check:repo`, `check:spec`) corre local y sin credenciales a través de
  `scripts/env.sh`. `scripts/acceptance.sh <archivo>` elige el runner por extensión (`.py` → `uv run pytest`,
  `.tftest.hcl` → `terraform test`, `.test.mjs` → `node --test`) y resuelve S-10.
- DEC-001: `npm run check:repo` falla si `infra/` declara `google_composer_environment` o fija en un recurso una región
  literal en vez de `var.region`. También falla ante IDs de proyecto o números de cuenta literales en `infra/`.
- DEC-004: `npm run check:repo` falla ante `credentials_json`, una llave de cuenta de servicio o un
  `google_secret_manager_secret_version` con `secret_data`. `.gitignore` deja fuera de git `.env*`, `*.tfvars` (salvo
  `*.tfvars.example`; Q-03: `alert_email`) y `*.tfstate*`.
- Esqueleto andante: `infra/bootstrap` e `infra/main` validan, `compras_ingest` tiene una prueba trivial que pasa y
  `dataform/` compila con una declaración de fuente en `us-central1`. Sin cambios en GCP.
- El `verify` declarado sale en 0 e imprime conteos de node:test, que `record_evidence.py` sabe leer:
  `scripts/env.sh bash -c 'npm run lint && npm test && npm run check:repo && npm run check:spec'`.

## Pasos
1. **Versiones.** Fijar en `mise.toml` (sección `[tools]`) versiones exactas, sin rangos:
   - `terraform`: la 1.x estable más reciente, ≥ 1.7, porque `mock_provider` y `terraform test -test-directory` lo exigen;
   - `uv`: la 0.x más reciente;
   - `python`: el último parche de 3.12, precompilado (`python.compile = false`);
   - `node`: el último parche de 22.

   En `[settings]` va `lockfile = true` (y `experimental = true` si la versión de mise elegida todavía lo pide para el
   lockfile). En `scripts/setup.sh` van `MISE_VERSION`, la última release estable de `jdx/mise`, y una tabla con el
   sha256 del binario suelto `mise-v<ver>-<plataforma>` para `linux-x64`, `linux-arm64`, `macos-x64` y `macos-arm64`.
   Los hashes se copian del `SHASUMS256.txt` de esa release.
2. **`scripts/env.sh <comando…>`** (bash, `set -euo pipefail`):
   - Calcula `ROOT` desde `BASH_SOURCE` y `TOOLS="$ROOT/.tools"`. Si `"$TOOLS/bin/mise"` no es ejecutable o falta la
     marca `"$TOOLS/.setup-ok"`, escribe a stderr `.tools/ is missing or incomplete; run scripts/setup.sh` y sale con 1.
     Sin argumentos, imprime el uso y sale con 2.
   - Exporta:
     - `MISE_DATA_DIR=$TOOLS/mise`, `MISE_CONFIG_DIR=$TOOLS/mise-config`, `MISE_CACHE_DIR=$TOOLS/cache/mise`,
       `MISE_STATE_DIR=$TOOLS/state/mise`;
     - `MISE_CEILING_PATHS="$(dirname "$ROOT")"`, para que mise no lea configuraciones de directorios superiores como
       `~/mise.toml`;
     - `MISE_TRUSTED_CONFIG_PATHS="$ROOT"`, `MISE_EXEC_AUTO_INSTALL=false` (`mise exec` nunca descarga) y `MISE_YES=1`;
     - `UV_PYTHON_DOWNLOADS=never`, `UV_PYTHON_PREFERENCE=only-system`, `UV_CACHE_DIR=$TOOLS/cache/uv`;
     - `npm_config_cache=$TOOLS/cache/npm`, `npm_config_update_notifier=false`;
     - `CHECKPOINT_DISABLE=1`, `TF_IN_AUTOMATION=1`, `TF_CLI_CONFIG_FILE=$TOOLS/terraform.rc`;
     - `PATH=/usr/bin:/bin`, que descarta el PATH global, y la marca `COMPRAS_ENV=1`.
   - Si el directorio actual no está dentro de `ROOT`, hace `cd "$ROOT"`, para que mise encuentre `mise.toml`.
   - Termina con `exec "$TOOLS/bin/mise" exec -- "$@"`. Es reentrante: llamarlo desde un script de npm que ya corre bajo
     `env.sh` vuelve a dar el mismo entorno.
3. **`scripts/setup.sh [--relock]`** (bash, `set -euo pipefail`, idempotente):
   1. Detecta la plataforma con `uname -s` y `uname -m`. Si no está en la tabla, sale con un error.
   2. Si `.tools/bin/mise` falta o su sha256 no coincide, descarga
      `https://github.com/jdx/mise/releases/download/v$MISE_VERSION/mise-v$MISE_VERSION-<plataforma>` a un archivo
      temporal con `curl -fsSL`. Verifica el sha256 con `sha256sum`, o `shasum -a 256` en macOS; si no coincide, borra el
      archivo y sale con un error. Si coincide, le da `chmod +x` y lo mueve a `.tools/bin/mise`. Nunca usa el `mise` del
      PATH.
   3. Exporta las mismas variables `MISE_*` que `env.sh` y escribe `.tools/terraform.rc` con
      `provider_installation { filesystem_mirror { path = "<ROOT>/.tools/providers" } }`.
   4. Con `--relock`, regenera los lockfiles y sigue con la instalación. Este modo deja la red solo en `setup.sh`:
      - `mise lock` para las cuatro plataformas;
      - `uv lock`;
      - `npm install --package-lock-only` en `dataform/`;
      - `terraform providers lock -platform=linux_amd64 -platform=linux_arm64 -platform=darwin_arm64 -platform=darwin_amd64`
        en `infra/bootstrap` y en `infra/main`. Este paso corre sin `TF_CLI_CONFIG_FILE`, para llegar al registro.
   5. Corre `.tools/bin/mise install`, que verifica contra `mise.lock`, y escribe la marca `.tools/.setup-ok`.
   6. Corre `scripts/env.sh uv sync --all-packages --locked`. Crea `.venv/` en la raíz con los miembros y el grupo `dev`.
   7. Corre `scripts/env.sh npm ci --prefix dataform`.
   8. En `infra/bootstrap` y en `infra/main`:
      - `scripts/env.sh env -u TF_CLI_CONFIG_FILE terraform -chdir=infra/<raíz> providers mirror "$ROOT/.tools/providers"`.
        Respeta el `.terraform.lock.hcl` versionado.
      - `scripts/env.sh terraform -chdir=infra/<raíz> init -backend=false -input=false -plugin-dir="$ROOT/.tools/providers"`.
   9. Imprime las versiones con `scripts/env.sh bash -c 'terraform version; uv --version; python --version; node --version'`.

## Supuestos
- Cada release de `jdx/mise` publica binarios sueltos `mise-v<ver>-<linux|macos>-<x64|arm64>` y un `SHASUMS256.txt`.
- mise respeta `MISE_DATA_DIR`, `MISE_CONFIG_DIR`, `MISE_CACHE_DIR`, `MISE_STATE_DIR`, `MISE_CEILING_PATHS`, `MISE_TRUSTED_CONFIG_PATHS`, `MISE_EXEC_AUTO_INSTALL` y `MISE_YES`.
- Con `lockfile = true`, `mise lock` escribe `mise.lock` con un checksum por plataforma, y `mise install` lo verifica.
- `mise exec -- <cmd>` antepone al PATH los directorios bin de las herramientas de `mise.toml`, así que `command -v` los resuelve antes que `/usr/bin`.
- El registro de mise instala terraform por aqua (`hashicorp/terraform`) verificando el SHA256SUMS de HashiCorp; python, desde python-build-standalone precompilado; node, desde nodejs.org con SHASUMS256.
- Una raíz de uv sin `[project]` es un workspace virtual que acepta `[dependency-groups]`, y `uv sync --all-packages` instala todos los miembros.
- `uv run --frozen` no vuelve a resolver ni descarga nada si `.venv` ya está sincronizado.
- Un miembro con `[tool.uv] package = false` no necesita backend de build ni código.
- `terraform providers mirror` escribe una estructura empaquetada que `init -plugin-dir` acepta, y respeta las versiones y los hashes de `.terraform.lock.hcl`.
- `terraform test` con `mock_provider` necesita el binario del proveedor instalado (por su esquema), pero no credenciales ni red.
- `terraform test` sin archivos de prueba sale en 0.
- Dataform CLI 3.x compila sin red ni credenciales.
- Dataform rechaza tener a la vez `dataformCoreVersion` en `workflow_settings.yaml` y `@dataform/core` en `package.json`.
- `dataform compile --json` expone `projectConfig.defaultLocation` y las declaraciones con `target.schema` y `target.name`.
- `record_evidence.py` cuenta solo los resúmenes de node:test (`ℹ tests N`); los de pytest y terraform no suman, y los de `test:ci`, `test:dataform` y `test:sdd` dan el conteo.
- Las pruebas de `test:sdd` solo necesitan `git`, `bash` y coreutils de `/usr/bin:/bin`, además de `node` y `python3` de `.tools/`.
- El implementador tiene red durante `scripts/setup.sh` y `scripts/setup.sh --relock`.

## Riesgos
- **Una versión de mise que todavía marca el lockfile como experimental, o en la que `mise lock` no existe.** Paso 1:
  se agrega `experimental = true` o se elige la release que lo trae. Si no hay ninguna, `notes` registra que los
  checksums quedan solo en la verificación de aqua y SHASUMS.
- **mise lee una configuración del usuario (`~/.config/mise`, `~/mise.toml`) y cambia una versión.** Paso 2:
  `MISE_CONFIG_DIR` apunta dentro de `.tools/` y `MISE_CEILING_PATHS` corta la búsqueda en el padre de la raíz.
- **`mise exec` descarga en medio de un `verify`.** Paso 2: `MISE_EXEC_AUTO_INSTALL=false`.
- **Terraform contacta checkpoint o el registro en el `verify`.** Paso 2: `CHECKPOINT_DISABLE=1` y `TF_CLI_CONFIG_FILE`
  con solo `filesystem_mirror`. Paso 3.8: `init` con `-plugin-dir`.
- **uv descarga otro Python o usa uno global.** Paso 2: `UV_PYTHON_DOWNLOADS=never` y `UV_PYTHON_PREFERENCE=only-system`,
  con `PATH=/usr/bin:/bin` más mise. Paso 4: `requires-python = "==3.12.*"`. El paso 9a lo comprueba.
- **Un binario global en `/usr/bin` gana a `.tools/`.** El paso 9a falla si una ruta no empieza con `.tools/`.
- **El binario de mise llega alterado.** Paso 3.2: verificación de sha256 antes de `chmod` y mover. Si falla, se borra
  y se sale con un error.
- **`.terraform.lock.hcl` generado desde el mirror solo trae el hash h1 de una plataforma y CI (T-04) falla.** Paso 3.4:
  `providers lock` con cuatro plataformas antes del mirror.
- **`check-repo.mjs` se detecta a sí mismo o detecta la spec.** Paso 7: literales armados por concatenación y exclusión
  de `spec/`, `plans/`, `research/` y `*.md`. El caso positivo del paso 8 corre sobre un árbol limpio.
- **La regla `literal-region` choca con la validación de región de T-03.** Paso 7: excluye el `default` de variables y
  las listas dentro de `validation`.
- **La regla `\d{12}` da falsos positivos en `infra/`.** Paso 7: aplica solo a `infra/`. Paso 8: un caso de borde.
- **S-10 falla: `-test-directory` no acepta rutas fuera del módulo o `-filter` no las resuelve.** Paso 11: se comprueba
  en un directorio temporal. Paso 10: la rama que copia el archivo y lo borra con `trap`.
- **Un `.tftest.hcl` de T-03 apunta a `infra/bootstrap`.** Paso 10: la primera línea `# module: infra/<dir>`. El
  `module { source = "../bootstrap" }` de un `run` en `infra/main` también funciona porque ambas raíces fijan los mismos
  proveedores.
- **Dataform rechaza la configuración por tener la versión en dos lugares.** Paso 6: sin `dataformCoreVersion`.
- **`test:sdd` falla bajo el PATH restringido.** Paso 14: se corre la Verificación completa. Si una prueba de sdd-base
  necesita un binario fuera de `/usr/bin:/bin`, no se edita (está fijada en `.sdd-base.json`). Se registra en `notes` y
  se pide `blocked_by: DEC-005`.
- **Una herramienta de lint marca archivos de sdd-base que no se pueden editar** (`scripts/record_evidence.py`).
  Paso 12: `ruff` corre solo sobre `ingest`, `finops` y `benchmarks`.
- **Un commit toca algo fuera de `touches` (`plans/`, `spec/`, `tests/acceptance/`).** Paso 15: los archivos se agregan
  uno por uno desde la lista de Archivos.
